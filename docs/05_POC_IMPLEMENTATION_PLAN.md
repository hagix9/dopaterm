## 1. Phase 1（最小PoC）のGO条件

設計書Rev.3第11節に基づく、Phase 1の実装着手・完了判定基準（GO条件）は以下の通りです。

### 1.1 Phase 1 実装着手条件 (Design Gate)
- [x] 技術選定（node-pty, ws, TypeScript, xterm.js, Canvas 2D, Web Audio）の確定。
- [x] 参考実装（Dopa Drill）からの素材完全分離とオリジナルアート方針の確立。
- [x] PTYデータプレーンとエフェクトコントロールプレーンの分離方式（デュアルWS）の確定。
- [x] OSC 133（Shell Integration）を用いた安全なコマンド開始・終了・exit code取得設計の確定。
- [x] Loopbackセキュリティ（Origin検証 + ランダムトークン）の仕様確定。

### 1.2 Phase 1 完了判定条件 (PoC Success Criteria)
1. **実際のファイルコピーの成功**:
   - `cp -R test_src test_dst` をDopaterm上で実行した際、OS標準の `cp` コマンドが実行され、ファイルが実際に正しくコピーされること。
2. **過剰演出の発火**:
   - コマンド実行中、ファイルが飛翔するアニメーションおよび「FILE TRANSFER」バナーが表示されること。
3. **成功時のみの紙吹雪**:
   - `exit code === 0` が確認された場合のみ、「✨ PERFECT COPY ✨」ポップアップと紙吹雪（Confetti）が盛大に舞うこと。
   - 存在しないファイルを指定して `cp` が失敗（exit code != 0）した場合は、成功演出が絶対に発火しないこと。
4. **迅速な自動退場**:
   - 演出完了後、0.5〜1.0秒以内にエフェクトがフェードアウト退場し、ターミナルの通常表示に復帰すること。
5. **シェル操作の不可侵性**:
   - 演出中および演出終了後も、ユーザーのキー入力、出力表示、スクロール、コピー＆ペーストが妨害されず、通常のシェル操作が継続できること。
6. **不変条件の遵守**:
   - `exit code` や `stdout/stderr` を改変しないこと。
   - 架空の転送量（GB数等）を実測値として表示しないこと。

## 2. Phase 1 最小作業順序 (Step-by-Step Execution Plan)

以下の5ステップで、最短経路にて紙吹雪を表示します。

```text
Step 1: バックエンド基盤 (Node.js + loopback + 認証トークン + node-pty + WebSocket)
   │
Step 2: フロントエンド基盤 (Vite + TypeScript + xterm.js + デュアルWS接続疎通)
   │
Step 3: シェル連携とコマンド検出 (安全なOSC 133フック注入 + イベント発行)
   │
Step 4: エフェクトエンジン構築 (オリジナルSVGマスコット + Canvas紙吹雪 + Web Audio)
   │
Step 5: 統合検証・安全性テスト (正常コピー、エラーコピー、負荷テスト、退場確認)
```

### Step 1: バックエンド基盤
- プロジェクト構成（`package.json`, `tsconfig.json`）の作成。
- `server/index.ts`: Loopback (`127.0.0.1`) 専用HTTP/WebSocketサーバー。
- 暗号セッショントークン生成とOrigin検証ミドルウェア。
- `node-pty` によるシェルプロセス起動と、OSC 133連携スクリプトの動的読み込み。

### Step 2: フロントエンド基盤
- Vite + TypeScript プロジェクト構成。
- `client/terminal.ts`: xterm.js のセットアップ、FitAddonによるレスポンシブリサイズ。
- `/ws/pty` 接続による双方向ストリーミング疎通（通常のターミナルとして動作確認）。

### Step 3: コマンド観測・イベント契約の実装
- `client/osc-parser.ts`: `terminal.parser.registerOscHandler(133)` の実装。
- `client/input-watcher.ts`: キーストローク観測による `command_candidate` 発行。
- `client/effect-director.ts`: イベント契約に基づくステートマシンの実装。

### Step 4: エフェクトエンジン実装
- `client/mascot.ts`: オリジナルマスコット「ターミにゃん」のインラインSVG + Spring物理アニメーション。
- `client/particles.ts`: Canvas 2D による紙吹雪（Confetti）および飛ぶファイル（Flying Docs）。
- `client/audio.ts`: Web Audio API による動的シンセサイザー（ファンファーレ、コピーSE）。
- `client/ui-overlay.ts`: CSS Transitions による「PERFECT COPY」バナー。

### Step 5: 結合・検証
- テスト用ディレクトリ・ファイルを作成し、`cp` 実行シナリオの自動/手動検証を実施。

## 3. 検証テスト計画 (Test Matrix)

| テストID | シナリオ | 入力コマンド | 期待される挙動 | 合否判定 |
|---|---|---|---|---|
| **TC-01** | **正常コピー** | `cp file_a.txt file_b.txt` | 実ファイル作成確認、コピー演出、成功バナー表示、紙吹雪噴出、0.8秒で退場 | 必須 |
| **TC-02** | **再帰的コピー** | `cp -R dir_a dir_b` | ディレクトリ完全コピー、同様に過剰演出と紙吹雪 | 必須 |
| **TC-03** | **エラー終了** | `cp non_existent_file.txt dst.txt` | stderrに「No such file」表示、**成功バナー・紙吹雪は絶対に出ない**、演出静止退場 | 必須 |
| **TC-04** | **演出OFF** | Level 0設定で `cp a b` | 演出レイヤーが無反応、通常ターミナルとして動作 | 必須 |
| **TC-05** | **エフェクト障害隔離** | Canvas/Audio内で意図的に例外送出 | コンソール警告のみで、ターミナルキー入力・シェル出力が1フレームも停止しない | 必須 |
| **TC-06** | **非対象コマンド** | `ls -la`, `mkdir test`, `pwd` | Phase 1では特殊演出を出さず、通常のターミナル出力のみ | 必須 |
| **TC-07** | **画面操作性** | 演出発火中にマウスで文字列選択 | `pointer-events: none` により問題なく文字選択・コピー可能 | 必須 |
| **TC-08** | **コンボ進化** | `cp` を連続10回、100回実行 | COMBO!（金貨・倍率）、FEVER!!（虹色トンネル・花火）の段階的演出昇格を確認 | 必須 |
| **TC-09** | **TYPO激突演出** | 存在しないコマンド `cpx` 実行 | stderrに「command not found」検知、巨大TYPOブロック激突、成功演出非発火 | 必須 |
| **TC-10** | **権限拒否演出** | 権限のないファイルへ `cp` | stderrに「Permission denied」検知、巨大南京錠落下、成功演出非発火 | 必須 |
| **TC-11** | **デモモード完全性** | デモパネルから10,000回特異点・DISASTER再生 | 画面上で過剰演出がフル再生されるが、シェル/PTYへの実コマンド送信がゼロであること | 必須 |
| **TC-12** | **負荷耐性・FPS保護** | スクリプトで1秒間に50回 `cp` 連打 | イベントスロットル発火、描画パーティクル上限800個クランプ、FPS低下時に自動品質退避、シェル停止なし | 必須 |

## 4. リスク分析と対策 (Risk Assessment & Mitigation)

| リスク要因 | 影響度 | 発生確率 | 対策 (Mitigation) |
|---|---|---|---|
| **CSWSH (悪意サイトからのローカル接続)** | **極大** | 中 | ワンタイム暗号トークン照合 ＋ Originヘッダー厳密検証（外部Originは403拒否）。 |
| **シェルフックによるユーザー設定汚染** | **大** | 低 | 既存の `.zshrc` ファイル本体を一切書き換えず、PTY起動プロセス内の環境変数（メモリ内）経由でのみ一時ロードする。 |
| **対話型ツール（vim等）での誤動作** | **中** | 中 | OSC 133 によるプロンプト開始/終了シグナルがない状態（対話中）は、入力観測演出を完全に無効化。 |
| **大量描画によるFPS低下・プチフリ** | **中** | 低 | パーティクルオブジェクトプールの適用、DeltaTimeによる動的間引き、RAFループ外でのDOM操作排除。 |
| **ブラウザのAutoplay制約による無音** | **低** | 高 | 初回キー押下またはクリック時に透過的に `AudioContext.resume()` を呼出し、エラーを抑制。 |
